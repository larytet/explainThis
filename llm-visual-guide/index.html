1 · Next-token prediction Transformer Explainer · 3Blue1Brown

Real thing: poloclub.github.io/transformer-explainer runs a live GPT-2 in your browser.

A model turns the text so far into a score (logit) for every token in its vocabulary. Softmax makes probabilities; temperature and top-k shape how the next token is picked.

Prompt: Thecatsatonthe▁?
Low temperature → the top token dominates (near-greedy). High temperature → the distribution flattens. Top-k zeroes out everything below rank k, then renormalises.

2 · Self-attention: Q, K and V Illustrated Transformer · LLM Visualization

Real things: The Illustrated Transformer · bbycroft.net/llm (3D walk through nano-GPT).

Each token makes a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what I hand over"). Weights = softmax(Q·K / √d), masked so a token only sees the past. Click a token to see where it looks. Three hand-made "heads" show that heads specialise.

3 · Attention variants and the KV cache Visual Guide to Attention Variants

Real thing: Raschka — A Visual Guide to Attention Variants in Modern LLMs (MHA, GQA, MLA, sparse and hybrid).

During generation every past token's keys and values are cached. Variants differ mainly in how much they cache per token. Set a model shape and compare (bytes = 2 for fp16/bf16).

MHA: 2·L·H·d per token. MQA: one shared K/V head. GQA: G shared groups. MLA: caches one compressed latent (plus a small RoPE part, 64 here) per layer. Sliding window: full MHA cost but capped at the window. Simplified formulas — real models mix layer types (the "hybrid" part of the article).

4 · Mixture of Experts routing Visual Guide to MoE

Real thing: Maarten Grootendorst — A Visual Guide to Mixture of Experts.

A router scores 8 experts for each token and sends it to the top-k. Left alone, a router tends to favour a few "popular" experts and the rest sit idle. A load-balancing term nudges it towards an even spread.

5 · Inference: prefill, decode and the KV cache LLM Inference Handbook

Real thing: Modular — LLM Inference Handbook.

Inference = prefill (process the whole prompt in parallel) then a decode loop (one new token per step). Without a KV cache, every step re-processes everything so far.

Legend: blue = tokens computed this step, grey = tokens served from cache, orange outline = newest token. Prefill is compute-bound (big parallel matmul); decode is memory-bandwidth-bound (re-reads weights + cache each token). Cache saves compute but costs memory — see section 3.

6 · Train a tiny neural network TensorFlow Playground · 3Blue1Brown

Real things: playground.tensorflow.org · 3Blue1Brown neural networks. This one is a from-scratch MLP (tanh, SGD) running in your browser.
Try: 1 layer × 2 neurons on Spiral (can't fit), then 3 × 8. Try learning rate 0.3 and watch it destabilise.

7 · What do features represent? Neuronpedia

Real thing: neuronpedia.org hosts real interpretability features (sparse autoencoder latents) with top-activating text, search and steering.

Interpretability researchers find features: directions inside the model that light up for a concept. Type text; a toy keyword lexicon stands in for the real feature detectors.

Steering here nudges a made-up next-word distribution towards the chosen feature's words — the same idea as real feature steering, with none of the real model.

8 · Embedding map Embedding Atlas

Real thing: Apple's Embedding Atlas for exploring large embedding sets with clusters, search and metadata.

Embeddings place similar things near each other. Below, 48 words with hand-placed 2D positions. Hover to see nearest neighbours (cosine on the 2D vectors); search to highlight; click a point to pin it.
