0 · The statistics you'll need

The slides that follow lean on a handful of ideas from probability. Type a few numbers — think of them as a model's scores for a few possible next tokens — and every idea below is computed step by step on your numbers.

Mean
Normalise (divide by the total)

Argmax (what greedy picks)
Odds: top vs runner-up
Log-probabilities
Entropy (how uncertain)
Sampling (randomness)
Try −1, 0, 4: plain normalising fails on the negative number, softmax still works. Try 1, 1, 1, 1: equal scores give equal probabilities (0.25 each), the most uncertain a choice can be, so entropy hits its maximum (2 bits) and argmax is a tie. Entropy is low when one score dominates, e.g. 10, 0, 0, 0 → H ≈ 0.

1 · Next-token prediction Transformer Explainer · 3Blue1Brown

A model turns the text so far into a score (logit) for every token in its vocabulary. Softmax makes probabilities; temperature and top-k shape how the next token is picked.

Prompt: Thecatsatonthe▁?
Low temperature → the top token dominates (near-greedy). High temperature → the distribution flattens. Top-k zeroes out everything below rank k, then renormalises.

2a · Self-attention: the goal why Q, K and V exist

A word's embedding means the same thing in every sentence, but meaning depends on context. The goal of self-attention: let each token update its own vector with information pulled from the other tokens that matter to it. Change the last word below and watch which noun gets pulled in.

The animal didn't cross the street because it was too
Q · query = the search: "what am I looking for?"
K · key = the label: "what do I offer, how do I get found?"
V · value = the content: "what I hand over if chosen".
Like a library: your search terms (Q) are matched against catalogue entries (K), and you take home the books' text (V).
Why does the last word ask the question, not "it"? With the causal mask a token only sees the past, so "it" cannot see "tired" yet. The word that settles the meaning looks back and asks "what can be tired?" (or "what can be wide?"). Why are K and V separate? What makes a token relevant (it is something that can get tired) differs from what you want to take from it (what an animal is). Query strength 0 → every score is 0 → a plain average: no preference. Toy numbers with 2-dimensional vectors, and only the two nouns are scored to keep the arithmetic small. The next slide runs the same mechanism over the whole sentence, with several heads and the causal mask.

2c · One model, many languages tokenisation · data

The same transformer, with the same next-token prediction and the same attention, serves every human language and code. Nothing in the architecture is English-specific. What differs is how text is cut into tokens and how much training text exists. Below, one sentence in eight languages runs through two toy tokenizers.

What stays the same
• One model, one shared vocabulary, one set of weights for all languages.
• Attention learns word order from data: verb-second (English), verb-last (Japanese) and free order (Latin) just give different attention patterns.
• Concepts are shared: "cat", "Katze" and "猫" land near each other in embedding space, so skills learned in one language often transfer.
What differs
• Tokenisation: badly covered languages need more tokens for the same meaning → slower, costlier, less fits in the context.
• Morphology: Finnish "matolla" = "on the mat"; Russian nouns change form by case. More word forms to learn.
• Data: English has trillions of tokens of text, many languages a thousandth of that or less. The biggest real gap.
• Code is just another token sequence, with the bonus that output can be checked by running it.

3 · Attention variants and the KV cache Visual Guide to Attention Variants

During generation every past token's keys and values are cached. Variants differ mainly in how much they cache per token. Set a model shape and compare (bytes = 2 for fp16/bf16).

MHA: 2·L·H·d per token. MQA: one shared K/V head. GQA: G shared groups. MLA: caches one compressed latent (plus a small RoPE part, 64 here) per layer. Sliding window: full MHA cost but capped at the window. Simplified formulas — real models mix layer types (the "hybrid" part of the article).

4 · Mixture of Experts routing Visual Guide to MoE

A router scores 8 experts for each token and sends it to the top-k. Left alone, a router tends to favour a few "popular" experts and the rest sit idle. A load-balancing term nudges it towards an even spread.

5 · Inference: prefill, decode and the KV cache LLM Inference Handbook

Inference = prefill (process the whole prompt in parallel) then a decode loop (one new token per step). Without a KV cache, every step re-processes everything so far.

Legend: blue = tokens computed this step, grey = tokens served from cache, orange outline = newest token. Prefill is compute-bound (big parallel matmul); decode is memory-bandwidth-bound (re-reads weights + cache each token). Cache saves compute but costs memory — see section 3.
